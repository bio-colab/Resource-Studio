# خطة اختبار MCP في Resource Studio

## 1. اختبارات البروتوكول

| المعرّف | الاختبار | معيار القبول |
|---|---|---|
| MCP-P-01 | تهيئة stdio | يعلن الخادم الهوية، النسخة، والقدرات الصحيحة |
| MCP-P-02 | `tools/list` | ترتيب ثابت، أسماء فريدة، schemas صحيحة |
| MCP-P-03 | `tools/call` قراءة | نتيجة structuredContent وisError صحيحان |
| MCP-P-04 | `resources/read` | URI صالح، MIME صحيح، وعدم تسريب مسار غير مسموح |
| MCP-P-05 | نسخة غير مدعومة | خطأ تفاوض واضح مع الإصدارات المدعومة |
| MCP-P-06 | listChanged | إشعار عند إضافة plugin أو أداة حسب السياسة |

## 2. اختبارات النواة

| المعرّف | الاختبار | معيار القبول |
|---|---|---|
| CORE-01 | فهرسة PE 32-bit | type/name/language والحجم والبصمة صحيحة |
| CORE-02 | فهرسة PE 64-bit | لا تعتمد النواة على حجم ترويسة ثابت خاطئ |
| CORE-03 | ملف متعدد اللغات | كل لغة تظهر كمورد مستقل |
| CORE-04 | مورد غير معروف | raw bytes وHex دون تنفيذ المحتوى |
| CORE-05 | مقارنة ملفين | حالات added/removed/modified/unchanged دقيقة |
| CORE-06 | توقيع Authenticode | الحالة قبل وبعد واضحة |

## 3. اختبارات التخطيط والتعديل

| المعرّف | الاختبار | معيار القبول |
|---|---|---|
| MUT-01 | خطة إضافة | لا كتابة قبل apply والتأكيد |
| MUT-02 | خطة حذف | يعرض النوع والاسم واللغة المتأثرة |
| MUT-03 | هاش مصدر متغير | رفض التنفيذ وإعادة إنشاء الخطة |
| MUT-04 | مسار الأصل | رفض أي محاولة كتابة إلى originalPathsReadOnly |
| MUT-05 | apply بلا confirmation | رفض صريح |
| MUT-06 | إعادة فتح الناتج | فهرسة الناتج ومقارنتها بالخطة |
| MUT-07 | فشل المحرك | لا يصدر الخادم ناتجًا ناجحًا مضللًا |
| MUT-08 | التراجع | استعادة snapshot مع بقاء audit كامل |

## 4. اختبارات أمن MCP

| المعرّف | الاختبار | معيار القبول |
|---|---|---|
| SEC-01 | path traversal | رفض `..` والمسارات خارج الجذر |
| SEC-02 | symlink/junction | عدم الكتابة عبر رابط غير مصرح |
| SEC-03 | arbitrary command | لا توجد أداة تنفيذ عامة |
| SEC-04 | oversized input | رفض أو تدفق محدود فوق الحد |
| SEC-05 | prompt injection داخل مورد | تعامل المحتوى كبيانات لا كتعليمات |
| SEC-06 | إعادة استخدام confirmation | رفض الرمز المنتهي أو المستخدم سابقًا |
| SEC-07 | نقل بعيد | اختبار Origin/auth/scope/SSRF قبل التفعيل |
| SEC-08 | سجل التدقيق | لا توجد أسرار أو محتويات خام غير لازمة |

## 5. اختبارات التوافق

تُحفظ fixtures لطلبات v1 ونتائجها. كل تغيير في schema يشغّل اختبارات العملاء السابقة. الإضافات المتوافقة لا تغير الحقول المطلوبة. التغييرات الكاسرة تنشئ namespace أو إصدارًا جديدًا وتبقي الإصدار السابق خلال فترة الهجرة.

## 6. بوابة الإصدار

لا تنتقل أداة من مرحلة القراءة إلى التخطيط قبل نجاح جميع اختبارات MCP-P وCORE. ولا تنتقل إلى التعديل قبل نجاح MUT وSEC-01 إلى SEC-06. ولا يفعّل النقل البعيد أو plugins ذات الصلاحيات قبل مراجعة SEC-07 وSEC-08 وتوقيع قرار معماري جديد.
