# خارطة طريق Resource Studio مع MCP

## المرحلة صفر: الأساس والعزل

تثبيت مساحة العمل، حماية المسار الأصلي، فهرسة الموارد، حفظ الهاشات، وتسجيل كل عملية. لا يوجد MCP تعديل في هذه المرحلة؛ يوجد MCP قراءة أولي فقط.

**معيار القبول:** يمكن فتح ملف، استخراج manifest الموارد، عرض التوقيع والهاش، وعدم وجود أي مسار كتابة إلى النسخة الأصلية.

## المرحلة الأولى: MCP قراءة فقط

إضافة `inspect_file` و`index_resources` و`get_resource` و`preview_resource` و`diff_files` و`verify_signature` و`read_audit`. دعم stdio، `tools/list`، `tools/call`، الموارد URI، والمخرجات المنظمة.

**معيار القبول:** يكتشف عميل MCP الأدوات، ويعيد كل نداء schema ثابتًا، وتعمل الاختبارات على ملف اختبار سليم وملف غير موثوق وملف متعدد اللغات.

## المرحلة الثانية: التخطيط وDry-run

إضافة `create_workspace` و`plan_resource_change` و`plan_extract` و`plan_localization`. لا تكتب أدوات التخطيط شيئًا؛ تنتج planId، diff، تحذيرات، وconfirmation summary.

**معيار القبول:** يمكن رفض الخطة أو تعديلها قبل أي كتابة، ويظهر الفرق المتوقع قبل التنفيذ.

## المرحلة الثالثة: التعديل المعزول

إضافة `apply_plan` و`commit_resource` و`export_workspace`. تستدعي النواة أو adapter Resource Hacker، وتعيد فتح الناتج وفهرسته والتحقق من مطابقته للخطة.

**معيار القبول:** جميع وظائف مصفوفة Resource Hacker الحالية تمر، ويُمنع التعديل المباشر للأصل، وتُسجل البصمات قبل وبعد.

## المرحلة الرابعة: واجهة Resource Studio

بناء واجهة مقارنة، معاينات متخصصة، إدارة لغات، سجل تدقيق، واستعراض خطط MCP. الواجهة ليست مصدر منطق مستقل؛ تستدعي النواة نفسها.

**معيار القبول:** نفس العملية تعطي نفس النتيجة عبر UI وCLI وMCP، مع اختلاف العرض فقط.

## المرحلة الخامسة: PE Analyzer للقراءة فقط

إضافة headers، sections، imports، exports، relocations، TLS، debug، load configuration، CLR metadata عند توفره، وقراءة شهادة Authenticode.

**معيار القبول:** لا توجد أدوات تعديل لأقسام PE التنفيذية، وكل قيمة تعرض offset وRVA ومصدرها، مع اختبار ملفات 32-bit و64-bit و.NET.

## المرحلة السادسة: الترجمة والتوطين

إضافة تقارير اللغات الناقصة، مقارنة strings/dialogs/menus، قوالب نسخ لغة، ومراجعة Unicode/UTF-8/ANSI. تُبنى الاختبارات على ملفات متعددة اللغات.

**معيار القبول:** يكتشف التقرير الموارد الناقصة والمختلفة دون تغيير اللغة الأصلية تلقائيًا.

## المرحلة السابعة: MSIX/PRI/MRT Core

قارئ حزم MSIX، عارض manifest، فهرس PRI، عرض الموارد حسب اللغة والمقياس والثيم والتباين، ثم إعادة حزم اختيارية بعد استقرار القراءة.

**معيار القبول:** القراءة والمقارنة أولًا، وإعادة الحزم لاحقًا مع فحص التوقيع وإعادة التحقق.

## المرحلة الثامنة: النظام الإضافي

Plugin API لمحللات الموارد، مع manifest لكل plugin، إصدار عقد، صلاحيات، توقيع اختياري، واختبارات عزل. لا يسمح plugin بإضافة أدوات MCP كتابة تلقائيًا؛ يجب أن يسجل أدواته ويخضع لمراجعة الصلاحيات.

## معايير عابرة لكل المراحل

| المعيار | القاعدة |
|---|---|
| التوافق | لا كسر لعقد MCP v1 دون إصدار جديد |
| الاختبار | كل أداة لها اختبارات نجاح وفشل وحدود |
| الأمان | أقل صلاحية، مسارات معزولة، تأكيد للكتابة |
| السجل | كل عملية لها operationId وauditUri |
| التراجع | لا كتابة مباشرة قبل توفر snapshot قابل للاستعادة |
| الترخيص | Resource Hacker الأصلي يبقى خارج حزمة التوزيع حتى مراجعة الحقوق |
| التوثيق | كل تغيير عقد أو صلاحية يحدّث CHANGELOG وADR |
